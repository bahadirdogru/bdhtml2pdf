# bdhtml2pdf 0.1.2 (pre-release) against five engines on an i7-12800H, 2026-11-23

The five-engine comparison for release 0.1.2, on the i7-12800H laptop with
Fedora 45 (mains power, `throughput-performance` tuned profile, `performance`
governor), 10 runs per fixture. All five engines were measured again in this
run on the same machine with the same system packages and fonts, so this is
now the comparison to quote. The i7-6700 run of 0.1.1
([2026-11-22.md](2026-11-22.md)) shows the same engines on a slower machine.

bdhtml2pdf is built from `3a7b3b1` (fulgur `31f572d2`, Blitz `c13cfe7d`, as
pinned in `.github/upstream.env`). The other engines:

| Engine | Version | From |
|---|---|---|
| sghtmltopdf | 0.8.0 | `cargo install sghtmltopdf --version 0.8.0 --locked` |
| wkhtmltopdf | 0.12.6.1 (with patched qt) | the official `wkhtmltox-0.12.6.1-3.almalinux9.x86_64.rpm` (sha256 `357a587c…03524b`), unpacked with `rpm2cpio … \| cpio -idm` |
| Chromium | 157.0.8103.78 | the Fedora 45 package |
| WeasyPrint | 70.0 | `pip install weasyprint==70.0` in a virtualenv (Python 3.15) |

Everything below the line is the unedited output of:

```sh
SGH=… WK=… CHROME=chromium-browser WEASY=…/weasyprint bench/run.sh -n 10
SGH=… WK=… CHROME=chromium-browser WEASY=…/weasyprint bench/security.sh      # 40 s / 2 GB per run
```

## Changes since 0.1.1

- **No regressions.** Every correctness score and every security verdict is
  the same as in the 0.1.1 run on this machine
  ([2026-11-22-i7-12800h.md](2026-11-22-i7-12800h.md)).
- **Time and memory are unchanged** within run-to-run noise: bdhtml2pdf
  takes 0.07–0.10 s for the fixtures without a framework and 0.16 s for
  React, Vue and the 1000-row invoice. The 0.1.2 changes (right-to-left
  reading order, element languages and tabs in the PDF/UA structure, the
  `url()` crash fix) do not affect these fixtures' cost.

## Notes on this run

- **Correctness is read from the last of the 10 runs.** Chromium's
  `modern-js` is 18 or 19 of 19 from run to run, because headless Chromium
  fires `requestAnimationFrame` only when it produces a frame; it was 18
  here (19 in the 0.1.1 run).
- **`fonts.html` depends on the system fonts.** On this machine wkhtmltopdf
  passes the CJK check (6/8) and WeasyPrint fails the Arabic one (7/8).
  sghtmltopdf takes 1.2 s and writes a 19 MB PDF here, with one font
  embedded whole instead of as a subset (the CJK fallback font).
- **Install size.** wkhtmltopdf is 39 MB from the AlmaLinux 9 package.
  Chromium is `/usr/lib64/chromium-browser`. WeasyPrint is its virtualenv;
  Python and Pango from the system are not counted.
- **Page size.** Chromium prints Letter, the others A4, so page counts differ.
- **Security times are single runs,** not medians.
- **sghtmltopdf's and WeasyPrint's ✅ on the JavaScript cases** only reflect
  that they have no JavaScript.
