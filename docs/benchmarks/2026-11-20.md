# bdhtml2pdf 0.1.0 (pre-release) — benchmark results, 2026-11-20

bdhtml2pdf only, measured again after the size, memory and long-table work. The other
engines did not change; their results are in [2026-11-19.md](2026-11-19.md).

What changed since 2026-11-19:

- **Built for size** (`opt-level = "s"`): the binary is 22 MB with image output
  included (31.5 MB before, 25 MB in the 2026-11-19 run, which predates image
  output).
- **Fonts are no longer copied.** fulgur kept a private copy of every font
  file a page used. `fonts.html` falls back to a 57 MB CJK font and now takes
  34 MB instead of 147 MB.
- **One SVG library instead of two.** Blitz uses the same `usvg` version as
  fulgur's PDF writer.
- **Boa without `Temporal`** and its calendar and time zone data.
- **Long tables are 7 times faster.** In a page with a `lang` attribute
  every table cell queried fontconfig for fallback fonts again (fontique
  stores the answer only for languages it has data for, and Parley asks for
  two keys per text item). Blitz now looks the defaults up once.
  `invoice-large` takes 0.17 s instead of 1.07 s, faster than wkhtmltopdf
  (0.37 s) and Chromium (0.71 s).

Correctness and security did not change. One-page documents take
0.08–0.10 s (0.07–0.09 s on 2026-11-19) and use the same memory as before,
apart from `fonts.html`. This run also includes the features added since
(default Arial font, shrink-to-fit, the absolute-positioning fixes);
measured side by side on the same code, `opt-level = "s"` and
`opt-level = 3` took the same time on these pages.

Everything below the line is the unedited output of:

```sh
bench/run.sh -n 5
bench/security.sh      # 40 s / 2 GB per run
```
