# bdhtml2pdf 0.1.0 (pre-release) — benchmark results, 2026-11-19

First published run. bdhtml2pdf is built from Blitz master `b4ad543` with local
patches and fulgur on the `blitz-master` port (see
[architecture](../architecture.md#changes-to-upstream-projects)).

Everything below the line is the unedited output of:

```sh
SGH=… WK=… CHROME=chromium-browser bench/run.sh -n 5
SGH=… WK=… CHROME=chromium-browser bench/security.sh      # 40 s / 2 GB per run
```

## Notes on this run

- **Chromium `modern-js` 18/19.** The missing item is `requestAnimationFrame`.
  Headless Chromium only fires rAF when it produces a frame, so with
  `--print-to-pdf` the callback sometimes never runs. It fired in an earlier
  trial run, so read this as flaky, not as missing support. Every other
  Chromium item passes, including `Intl`.
- **wkhtmltopdf `modern-js` and frameworks 0.** QtWebKit cannot parse ES2015+
  (`<script type="module">`, classes, arrow functions), so those scripts never
  run.
- **sghtmltopdf `fonts.html` is 19 MB.** It embeds the CJK fallback font
  without subsetting (4 of 5 fonts subset).
- **bdhtml2pdf `fonts.html` uses 147 MB RSS.** Loading the system CJK fallback
  font, a large variable font, dominates its memory. Pages without CJK text
  stay around 31 MB.
- **bdhtml2pdf `ligature-text` fails.** `office` extracts as `ofce`; see
  [roadmap](../roadmap.md#known-issues).
- **bdhtml2pdf `invoice-large` takes 1.07 s,** the slowest engine on that
  fixture; see known issues.
- **Page size.** Chromium prints Letter (612×792) by default and the others
  print A4, so page counts differ slightly.
- **Security: sghtmltopdf's ✅ on the JavaScript DoS cases** only reflects that
  it has no JavaScript.
