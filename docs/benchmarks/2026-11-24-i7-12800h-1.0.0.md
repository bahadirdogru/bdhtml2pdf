# bdhtml2pdf 1.0.0 against five engines on an i7-12800H, 2026-11-24

The five-engine comparison for release 1.0.0, on the same i7-12800H laptop
and with the same system packages and fonts as the 0.1.3 run
([2026-11-24-i7-12800h.md](2026-11-24-i7-12800h.md)): Fedora 45, mains
power, `throughput-performance` tuned profile, `performance` governor,
10 runs per fixture. The run started at 14:08 local time (UTC+3).

bdhtml2pdf is **the published release binary**, not a local build:
`bdhtml2pdf-1.0.0-linux-x86_64.tar.gz` from the GitHub release (sha256
checked against its `.sha256` file), built by the release workflow from
tag `v1.0.0` (fulgur `5f01287f`, Blitz `4257684d`, as pinned in
`.github/upstream.env`). This is the file users download. The other
engines are the ones listed in the 0.1.2 run, except that the Fedora
Chromium package moved from 157.0.8103.78 to 158.0.8127.36.

Everything below the line is the unedited output of:

```sh
BD=…/bdhtml2pdf-1.0.0-linux-x86_64/bdhtml2pdf SGH=… WK=… CHROME=chromium-browser WEASY=…/weasyprint bench/run.sh -n 10
BD=… SGH=… WK=… CHROME=chromium-browser WEASY=…/weasyprint bench/security.sh      # 40 s / 2 GB per run
```

## Changes since 0.1.3

- **No regressions.** Every correctness score, every PDF (pages, size,
  fonts, raster images) and every security verdict is the same as in the
  0.1.3 run. The work since 0.1.3 (inline backgrounds, `::first-letter`,
  page CSS on inline SVG, percentage cells in auto-width tables, block
  links and images as link areas, PDF/UA tagging of captions,
  `aria-labelledby` and inline `role="img"`) is covered by the test
  suite, not by these fixtures.
- **Speed and memory are unchanged** within run-to-run noise: 0.068–0.096 s
  and 32–37 MB RSS for the one-page fixtures, React 0.148 s, the JS memory
  bomb stopped in 3.7 s at 47 MB. The 1000-row invoice's median here is
  0.158 s against 0.149 s for 0.1.3, and Vue 0.148 against 0.142 s; a
  separate run of the 1.0.0 binary, 25 times in a row on the same invoice
  without systemd-run, gave a median of 0.148 s, so we read the difference
  as noise. The 0.1.3 binary is no longer published, so the two could not
  be run side by side.
- **Chromium 158.** Its install is 442 MB instead of 432 MB; its times and
  memory are within ±5% of Chromium 157. Its `modern-js` is 19/19 in this
  run (18 or 19 from run to run, see the 0.1.3 notes).

## Notes on this run

- **Correctness is read from the last of the 10 runs.**
- The notes of the 0.1.2 run on fonts, install size, page size, security
