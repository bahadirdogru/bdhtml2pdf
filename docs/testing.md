# Test suites

All suites are HTML files under `tests/` that are **self-checking** or have
**machine-checkable expectations**. The same file goes through every engine
unchanged, and the result is read back from the PDF with poppler
(`pdftotext`, `pdffonts`, `pdfinfo`, `pdfimages`). Nothing is judged by eye.

| Suite | File | Checks | Scored by |
|---|---|---|---|
| CSS | `tests/fixtures/modern-css.html` | 11 | PASS/FAIL lines in the PDF text |
| JavaScript | `tests/fixtures/modern-js.html` | 19 | PASS/FAIL lines written by the script |
| Frameworks | `react.html`, `vue.html`, `preact/index.html` | 3 | text that only exists after the app rendered and a timer fired |
| HTML parsing | `tests/fixtures/html-parsing.html` | 7 | PASS/FAIL lines, plus character references |
| Turkish | `tests/fixtures/turkish.html` | 15 | exact strings, embedded font names, PDF title, JS PASS lines |
| Fonts | `tests/fixtures/fonts.html` | 8 | embedded font names and exact strings |
| Pagination | `invoice-large.html` (generated by `bench/run.sh`) | 3 | last row, totals, table header repeated on every page |
| PDF output | every fixture | — | page count, page size, file size, raster images, fonts embedded/subset |
| Security | `tests/security/*.html` | 16 | leaked markers, HTTP requests, time and memory limits |

## The PASS/FAIL technique

A check renders as `PASS <name>` only when the engine supports the feature,
and as `FAIL <name>` otherwise:

```html
<style>
  .c .p { display: none; }  .c .f { display: inline; }        /* fallback: FAIL */
  .has:has(i) .p { display: inline; } .has:has(i) .f { display: none; }
</style>
<li class="c has"><i></i><span class="p">PASS has</span><span class="f">FAIL has</span></li>
```

An engine that does not understand `:has()` ignores the rule and shows
`FAIL has`. An item counts as passed only when its PASS line is in the PDF
**and** its FAIL line is not. If both appear, as with `<template>` content
that should not render, the item fails. JavaScript checks write the same lines
from script, so an engine without JavaScript scores 0, not "unknown".

## CSS — `modern-css.html`

| Check | Feature |
|---|---|
| `vars` | custom properties, `var()` |
| `nesting` | native CSS nesting (`&`) |
| `has` | `:has()` relational selector |
| `is-where` | `:is()` and zero-specificity `:where()` |
| `not-list` | `:not()` with a selector list |
| `layer` | `@layer` cascade layers: a later layer beats a more specific earlier one |
| `media-range` | media query range syntax `(width >= 1px)` |
| `container-query` | `container-type` + `@container` |
| `nth-of` | `:nth-child(1 of .p)` |
| `gen-content` | `::after { content: … }` |
| `supports-selector` | `@supports selector(:has(a))` |

The same page has a visual section that the PASS/FAIL count cannot judge.
Check it in the PDFs the benchmark writes. It contains: grid with
`aspect-ratio`; `linear-gradient` in `oklch()` and `color-mix()`;
`border-radius`; flex with `gap` and `space-between`; subgrid; multi-column
with `column-rule`; a collapsed-border table; `clamp()` font size.

## JavaScript — `modern-js.html` and frameworks

Language: classes with private fields and static methods, optional chaining
and nullish coalescing, destructuring and spread, `Map`/`Set`,
`Array.prototype.at`/`flatMap`, `Object.groupBy`, `structuredClone`, typed
arrays, RegExp named groups, `Intl.NumberFormat('tr-TR')`, JSON with
non-ASCII keys.

DOM: `querySelectorAll`, `classList`/`dataset`, `DocumentFragment.append`.

Event loop: `async`/`await` with `setTimeout`, microtasks, `queueMicrotask`,
`requestAnimationFrame`, `fetch()` of a local JSON file.

Frameworks (UMD builds vendored under `tests/fixtures/vendor`, so no network
is needed):

- **React 18** renders a 50-row invoice. A `useEffect` timer then changes the
  status to `ÖDENDİ`. Pass means the PDF shows the state *after* the timer.
- **Vue 3** renders a list, and `mounted()` updates it after a timer
  (`güncellendi`).
- **Preact** renders a TodoMVC-style app (`todos`).

The page signals readiness with `window.status = 'ready'`, which works with
`--window-status ready` exactly as in wkhtmltopdf.

## HTML parsing — `html-parsing.html`

Malformed markup must produce the same tree as in browsers (WHATWG parsing
algorithm). The checks are:

- implied `<tbody>`;
- `<p>` closed by `<div>`;
- foster parenting of stray table content;
- the adoption agency algorithm for misnested `<b><i></b>`;
- `<div/>` that is *not* self-closing;
- inert `<template>` content;
- named and numeric character references.

## Turkish

`turkish.html` exists because Turkish breaks engines in ways Latin-1 text never
shows. Every line is checked as an exact string in the extracted PDF text, so
the text must survive glyph mapping, font subsetting and ToUnicode.

| Check | Content | Catches |
|---|---|---|
| `alphabet` | Ç ç Ğ ğ I ı İ i Ö ö Ş ş Ü ü (system font) | missing glyphs, broken ToUnicode maps |
| `font-face` | the same letters through an `@font-face` OTF (Comfortaa) | web fonts not loaded or not covering Latin Extended-A |
| `font-face-embedded` | Comfortaa appears in `pdffonts` | silent fallback to a system font |
| `bold`, `italic` | ÇĞİÖŞÜ çğıöşü in bold and italic | synthetic or missing faces |
| `pangram` | *Pijamalı hasta yağız şoföre çabucak güvendi.* | shaping and kerning across all letters |
| `upper-tr` | `text-transform: uppercase` on `istanbul ılık iğdır` with `lang="tr"` → **İSTANBUL ILIK İĞDIR** | language-insensitive mapping (gives `ISTANBUL`) |
| `lower-tr` | `lowercase` on `İSTANBUL IŞIK IĞDIR` → **istanbul ışık ığdır** | gives `i̇stanbul işik` |
| `capitalize-tr` | `capitalize` on `izmir ıspanak` → **İzmir Ispanak** | gives `Izmir` |
| `invoice-marks` | `Tutar 1.234,50 ₺ — KDV %20 “dâhil”` | Turkish lira sign, typographic quotes, circumflex |
| `pdf-title` | `<title>` with ÇĞİÖŞÜ çğıöşü becomes the PDF Title | UTF-16 metadata encoding |
| JS ×4 | `toLocaleUpperCase('tr-TR')`, `toLocaleLowerCase('tr-TR')`, `localeCompare(…, 'tr')` sorting `c < ç < d`, DOM string round trip | locale data missing from the JS engine |

## PDF output

For every fixture the benchmark records:

- the page count;
- the page size in points (A4 is 595×842; Chromium's default is Letter,
  612×792);
- the file size;
- the number of **raster images**. Text pages should have 0: a non-zero count
  on a text page means the engine rasterized something;
- fonts as total, embedded and subset. Subsetting keeps files small; an
  engine that embeds whole CJK fonts produces multi-megabyte PDFs.
